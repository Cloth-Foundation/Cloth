# Numeric range membership (2026-11-03)

## Confirmed design

The user confirmed numeric membership with `==` and `!=`, both operand orders,
integer and float support, and contextual literal widths:

```cloth
10 == 1..100        // true
100 != 1..100       // true
1..=100 == 100      // true
def<float<64>> x = 16777217.0
16777216.5..16777217.5 == x // true, with float64 literal endpoints
```

`==` returns bool membership; `!=` is its exact logical inverse. `..` excludes
the upper endpoint, `..=` includes it, and both include the lower endpoint.
Float membership tests the interval, not the values generated by a loop step.
The maintained runnable example is [RangeMembership.co](../../../../examples/RangeMembership.co).

## Integrated policies and boundaries

- Evaluate each numeric expression once in written order: value/start/end or
  start/end/value. Capture each result before later expressions can modify its
  source. Neither bound comparison skips endpoint evaluation. Ordinary enclosing
  `&&`/`||`, returns and runtime failures still skip subsequent evaluation.
- Membership computes `start <= value && value < end`, changing the second
  comparison to `<=` for an inclusive range. Reversed intervals are empty;
  equal endpoints are empty for exclusive ranges and singletons for inclusive
  ranges. Loop descending-step behavior is unchanged.
- One exact non-nullable numeric type applies to value and endpoints: signed or
  unsigned fixed integers at widths 1..65536, usize/isize, or float16/32/64.
  The checked value's fixed contract supplies literal context. If that value is
  itself contextual literal syntax, discover a fixed endpoint contract before
  defaulting. With no fixed contract, use ordinary literal defaults.
- Context also reaches arithmetic literal operands. Literals must fit that type.
  Already-typed mismatched widths, signedness, target identities or integer/float
  categories require explicit casts. Integer literals retain their category;
  use floating literal forms for float intervals. Bool, char, string and arrays
  are not numeric membership operands. Nullable values need ordinary presence
  proofs or non-null fallbacks.
- Preserve ordinary floating comparisons and declared-format rounding, with no
  tolerance or endpoint snapping. A NaN checked value is never a member, and
  `!=` returns true. Infinite checked values are outside every finite interval.
  Endpoint finiteness follows the existing range contract: reject closed known
  nonfinite endpoints during compilation; guard dynamic endpoints immediately
  after evaluating each, before evaluating subsequent expressions.
- Ranges bind below arithmetic/casts and above ordering/equality, so either
  `x == a..b` or `a..b == x` groups naturally. Parentheses and nested expression
  positions admit membership syntax. Loop headers still consume their own
  outer delimiters, rejecting chained delimiters.
- This feature supplies no standalone/stored range value, range-to-range
  equality, range arithmetic, range ordering, range truthiness or step syntax.
  Invalid membership contracts use C3070 / INVALID_RANGE_MEMBERSHIP. Literal
  overflow retains C3004/C3028. Stop on the first error before output/linker work.

## Source ownership and invariants

- `ExpressionParser` parses range delimiters as binary syntax at precedence 8.
  `ForLoopParser` stops at outer delimiters for both loop endpoints. The
  `rangeOrNull` extension identifies range syntax using canonical operator enums.
- `ExpressionTyping.rangeMembership` discovers numeric context and validates
  all three operands before emission. Record the range syntax with an empty
  result shape so metadata traversal can visit its children without inventing
  a first-class range type. Parent membership has bool result (or never when
  execution cannot continue). Existing binary traversal preserves declaration,
  completion, null-flow, metadata, effect and temporary-cleanup analysis.
  Preserve contextual float typing in operand hints, including nullable Elvis
  fallbacks. Exiting operands contribute no type hint, including types from
  unreachable alternatives. If every operand exits, use an internal literal
  context solely to validate syntax and retain the never result. Still check
  every operand's syntax/types even if runtime evaluation cannot reach it.
  Membership owns its numeric context independently of enclosing function
  parameters; report its intrinsic errors during overload probes rather than
  substituting an unrelated no-matching-call error. Restore ordinary probe
  behavior when leaving this intrinsic checking scope.
- `EmitExpression.emitRangeMembership` captures source operands once and applies
  the two shared predicates. `EmitRangeValues` owns range finite guards and
  signed/unsigned/wide/float comparisons for both membership and `EmitRangeLoop`.
  Keep arbitrary-width integer comparison in `EmitWideInteger`; do not narrow
  to host machine widths. Float16 comparisons use the existing float32 working
  representation after literal/storage rounding.

## Verification

`RangeMembershipTest` covers boundaries, both orders, inverse inequality,
precedence, stored bool results, loops/while, contextual literals/arithmetic,
all integer representations through 65536, float16/32/64, double precision,
half rounding, signed zero, NaN/infinite checked values, once-only effects,
operand snapshots, early returns, nullable proofs, snippets, invalid contracts,
literal overflow, dynamic finite guards and first-error CLI behavior.
It also executes a portable fixture on native Windows x64/x86 and verifies IR
and object emission across all nine supported ABI profiles. Native Linux,
AArch64, macOS and musl execution are not established by those object checks.

## Review fixes (2026-11-03)

The follow-up review found three problems:

- Operand type hints dropped the contextual-float flag for nullable Elvis
  expressions, rejecting valid float16/float64 checked values such as
  `(x ?: 16777217.0) == 16777216.5..16777217.5`. Forward that flag through
  `arrayElementHint`'s general expression path; arrays and inferred loop sources
  share this helper.
- All-exiting operands were rejected as nonnumeric, and an exiting conditional
  could contribute a misleading type from an unreachable alternative. Discover
  hints only from continuing operands and default from any continuing numeric
  expression before falling back to a private literal-checking context. Keep
  real return/break/continue behavior and ordinary skipped-code validation.
- Source-function argument probes replaced invalid membership and contextual
  literal-overflow errors with C3024. A scoped intrinsic-check flag now preserves
  the original C3070/C3004/C3028 diagnostics without changing overload selection
  or leaving probe state altered after nested checks or failures.

Five additional regressions cover these fixes plus full-cap wide/indexed operand
snapshots across later writes. The original width and all-exit regressions failed
before their fixes; the 104-test focused nullable/array/loop/literal/membership
run passed after fixing the width and completion paths. The diagnostic/overload
focused run passed 75 tests across four suites. The final
`.\gradlew.bat :Compiler:test --offline --console=plain --no-daemon` run passed
1099 tests across 87 suites, zero failures/errors/skips, in 4m35s. All 18
membership tests pass, including native Windows x64/x86 and all nine ABI
profiles' IR/object checks. New fallback/control-flow/snapshot regressions execute
on native Windows x64. Metadata, local links and `git diff --check` pass manual
publication checks; the previously noted unavailable PyYAML validator remains
an environment limitation.
